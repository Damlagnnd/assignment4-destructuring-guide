This project is a field guide about destructuring in JavaScript, TypeScript, and React.

It demonstrates:

- 12 destructuring forms in JavaScript
- The same 12 forms with TypeScript types
- 5 JavaScript destructuring pitfalls
- TypeScript typing topics T1–T5
- React props and children examples P1–P7
- JavaScript versus TypeScript comparisons
- Real execution outputs and personal observations
- Advanced destructuring experiments
- Automated destructuring and React tests
- Real-world examples from a previous React project

The examples are based on course grades, university information, task management, and React components.

## 2. Destructuring Field Guide

### Form 1: Array Destructuring from a Function

**Syntax:**

```javascript
const [x, y] = functionReturningArray();
```

**Example (`js/arrays.mjs`):**

```javascript
function getExamResults() {
  return [85, 92];
}

const [midterm, finalExam] = getExamResults();

console.log("form 1:", midterm, finalExam);
```

**Real output:**

```text
form 1: 85 92
```

**Use it when:**

A function returns multiple related values in a specific order.

**Watch out:**

Array destructuring depends on positions rather than variable names. If an element is missing, its value may become `undefined`.

In TypeScript, a tuple such as `[number, number]` can describe two numeric return values.

---

### Form 2: Skipping Elements and Rest Syntax

**Syntax:**

```javascript
const [, second, ...others] = list;
```

**Example (`js/arrays.mjs`):**

```javascript
const programmingLanguages = [
  "Python",
  "JavaScript",
  "TypeScript",
  "Java"
];

const [, secondLanguage, ...otherLanguages] =
  programmingLanguages;

console.log("form 2:", secondLanguage, otherLanguages);
```

**Real output:**

```text
form 2: JavaScript [ 'TypeScript', 'Java' ]
```

**Use it when:**

We want to skip an array position and collect the remaining elements.

**Watch out:**

The rest element must appear at the end of the pattern. An element at a missing position becomes `undefined`.

---

### Form 3: Swapping Variables

**Syntax:**

```javascript
[a, b] = [b, a];
```

**Example (`js/arrays.mjs`):**

```javascript
let firstScore = 70;
let secondScore = 95;

[firstScore, secondScore] = [secondScore, firstScore];

console.log("form 3:", firstScore, secondScore);
```

**Real output:**

```text
form 3: 95 70
```

**Use it when:**

Two variables need to exchange their values without a temporary variable.

**Watch out:**

The variables must allow reassignment. Variables declared with `const` cannot be reassigned.

---

### Form 4: Default Values in Arrays

**Syntax:**

```javascript
const [a = 1, b = 2] = array;
```

**Example (`js/arrays.mjs`):**

```javascript
const availableScores = [88];

const [quizScore = 0, projectScore = 100] =
  availableScores;

console.log("form 4:", quizScore, projectScore);
```

**Real output:**

```text
form 4: 88 100
```

**Use it when:**

An array might contain fewer elements than expected.

**Watch out:**

Defaults only apply when the extracted value is `undefined`. They do not replace `null`, `false`, or `0`.

---

### Form 5: Object Destructuring

**Syntax:**

```javascript
const { title, status } = object;
```

**Example (`js/objects.mjs`):**

```javascript
const task = {
  title: "Finish web assignment",
  status: "in-progress"
};

const { title, status } = task;

console.log("form 5:", title, status);
```

**Real output:**

```text
form 5: Finish web assignment in-progress
```

**Use it when:**

Multiple named properties need to be extracted from an object.

**Watch out:**

Object destructuring uses property names rather than positions. Destructuring directly from `null` or `undefined` produces a TypeError.

---

### Form 6: Renaming Object Properties

**Syntax:**

```javascript
const { property: newName } = object;
```

**Example (`js/objects.mjs`):**

```javascript
const student = {
  name: "Damla",
  department: "Computer Engineering"
};

const { name: studentName } = student;

console.log("form 6:", studentName);
```

**Real output:**

```text
form 6: Damla
```

**Use it when:**

A property name conflicts with another variable or a more descriptive local name is needed.

**Watch out:**

`name: studentName` creates the local variable `studentName`, not `name`.

In TypeScript, the colon in this destructuring pattern means renaming, not a type annotation.

---

### Form 7: Default Values in Objects

**Syntax:**

```javascript
const { property = defaultValue } = object;
```

**Example (`js/objects.mjs`):**

```javascript
const course = {
  name: "Advanced Web Programming",
  credits: undefined
};

const { credits = 4 } = course;

console.log("form 7:", credits);
```

**Real output:**

```text
form 7: 4
```

**Use it when:**

An object property is optional and requires a fallback value.

**Watch out:**

Defaults are applied to `undefined`, but not to `null`.

---

### Form 8: Object Rest Properties

**Syntax:**

```javascript
const { property, ...others } = object;
```

**Example (`js/objects.mjs`):**

```javascript
const project = {
  projectName: "Task Manager",
  language: "TypeScript",
  framework: "React"
};

const { projectName, ...projectDetails } = project;

console.log("form 8:", projectName, projectDetails);
```

**Real output:**

```text
form 8: Task Manager { language: 'TypeScript', framework: 'React' }
```

**Use it when:**

One property should be separated from the remaining object properties.

This is also useful when forwarding React props.

**Watch out:**

Object rest creates a shallow copy. Nested objects are not deeply cloned.

---

### Form 9: Nested Object and Array Destructuring

**Syntax:**

```javascript
const {
  location: { city },
  courses: [firstCourse]
} = university;
```

**Example (`js/objects.mjs`):**

```javascript
const university = {
  location: {
    city: "Istanbul",
    campus: "Atakoy"
  },
  courses: [
    "Web Programming",
    "Operating Systems"
  ]
};

const {
  location: { city },
  courses: [firstCourse]
} = university;

console.log("form 9:", city, firstCourse);
```

**Real output:**

```text
form 9: Istanbul Web Programming
```

**Use it when:**

Values are stored inside nested objects or arrays.

**Watch out:**

Missing nested objects can cause runtime errors. TypeScript nested object types and tuples can describe the expected structure.

---

### Form 10: Computed Property Names

**Syntax:**

```javascript
const { [key]: value } = object;
```

**Example (`js/objects.mjs`):**

```javascript
const grades = {
  midterm: 80,
  final: 95
};

const selectedExam = "final";

const { [selectedExam]: selectedGrade } = grades;

console.log("form 10:", selectedGrade);
```

**Real output:**

```text
form 10: 95
```

**Use it when:**

The property to extract is selected using a variable.

**Watch out:**

Square brackets are required for a computed property name. In TypeScript, `keyof` can restrict the key to valid object properties.

---

### Form 11: Function Parameter Destructuring

**Syntax:**

```javascript
function createTask({
  title = "Untitled",
  status = "todo"
} = {}) {
  return { title, status };
}
```

**Example (`js/params.mjs`):**

```javascript
function createTask({
  title = "Untitled",
  status = "todo"
} = {}) {
  return { title, status };
}

console.log(
  "form 11a:",
  createTask({
    title: "Complete Assignment 4",
    status: "in-progress"
  })
);

console.log(
  "form 11b:",
  createTask({ title: "Study React" })
);

console.log("form 11c:", createTask());
```

**Real output:**

```text
form 11a: { title: 'Complete Assignment 4', status: 'in-progress' }
form 11b: { title: 'Study React', status: 'todo' }
form 11c: { title: 'Untitled', status: 'todo' }
```

**Use it when:**

A function receives an options object containing optional properties.

**Watch out:**

The outer `= {}` handles calls without an argument. Individual defaults handle missing or `undefined` properties.

Passing `null` as the whole argument still causes an error.

In TypeScript, `TaskOptions` describes the allowed properties.

---

### Form 12: Destructuring in Loops

**Syntax:**

```javascript
for (const [key, value] of Object.entries(object)) {
  // Use the key and value
}
```

**Example (`js/params.mjs`):**

```javascript
const courseGrades = {
  JavaScript: 90,
  TypeScript: 95,
  React: 88
};

for (const [course, grade] of Object.entries(courseGrades)) {
  console.log("form 12 object:", course, grade);
}

const taskStatuses = new Map([
  ["Assignment 4", "in-progress"],
  ["Study React", "todo"]
]);

for (const [task, status] of taskStatuses) {
  console.log("form 12 map:", task, status);
}
```

**Real output:**

```text
form 12 object: JavaScript 90
form 12 object: TypeScript 95
form 12 object: React 88
form 12 map: Assignment 4 in-progress
form 12 map: Study React todo
```

**Use it when:**

We need to iterate through key-value pairs in objects or Maps.

**Watch out:**

`Object.entries()` creates an array of pairs. A Map is directly iterable.

In TypeScript, `Record<string, number>` and `Map<string, string>` specify the corresponding types.

## 3. Five JavaScript Pitfalls

All examples are implemented in `js/pitfalls.mjs`.

The actual output was obtained by running:

```bash
node js/pitfalls.mjs
```

### Pitfall 1: Destructuring Undefined

**Example:**

```javascript
try {
  const { title } = undefined;
  console.log(title);
} catch (error) {
  console.log("pitfall 1:", error.name, "-", error.message);
}
```

**Real output:**

```text
pitfall 1: TypeError - Cannot destructure property 'title' of 'undefined' as it is undefined.
```

**Explanation:**

Destructuring an object requires a valid value. Destructuring `null` or `undefined` throws a TypeError.

**Prevention:**

Check the value or provide a fallback object.

---

### Pitfall 2: Null Does Not Trigger Defaults

**Example:**

```javascript
const task = { title: null };

const { title = "Untitled" } = task;

console.log("pitfall 2:", title);
```

**Real output:**

```text
pitfall 2: null
```

**Explanation:**

A default value is only used when the property is `undefined`.

**Prevention:**

Use `??` when both `null` and `undefined` should be replaced.

---

### Pitfall 3: Renaming Does Not Create the Original Variable

**Example:**

```javascript
try {
  const student = { name: "Damla" };
  const { name: studentName } = student;

  console.log("renamed value:", studentName);
  console.log(name);
} catch (error) {
  console.log("pitfall 3:", error.name, "-", error.message);
}
```

**Real output:**

```text
renamed value: Damla
pitfall 3: ReferenceError - name is not defined
```

**Explanation:**

The new local variable is named `studentName`. The original property name is not separately declared as a local variable.

**Prevention:**

Use the renamed variable consistently.

---

### Pitfall 4: Existing Object Assignment Requires Parentheses

**Example:**

```javascript
let status = "todo";

const updatedTask = {
  status: "done"
};

({ status } = updatedTask);

console.log("pitfall 4:", status);
```

**Real output:**

```text
pitfall 4: done
```

**Explanation:**

When using an object destructuring assignment statement with an existing variable, parentheses are required to prevent `{}` from being parsed as a block.

**Prevention:**

```javascript
({ status } = updatedTask);
```

This experiment demonstrates the corrected version. The invalid statement was not executed.

---

### Pitfall 5: Missing Array Elements

**Example:**

```javascript
const grades = [90];

const [firstGrade, secondGrade] = grades;

console.log("pitfall 5:", firstGrade, secondGrade);
```

**Real output:**

```text
pitfall 5: 90 undefined
```

**Explanation:**

A missing array position becomes `undefined` rather than producing an exception.

**Prevention:**

Use a default value or check whether the element exists.

## 4. TypeScript Typing Topics: T1–T5

These examples are implemented in `ts/types.ts`.

### T1: Renaming Versus Type Annotations

**Example:**

```typescript
const task = {
  title: "Complete Assignment 4"
};

const { title: taskTitle } = task;

const { title: typedTitle }: { title: string } = task;
```

**Real output:**

```text
T1 renamed: Complete Assignment 4
T1 typed: Complete Assignment 4
```

**Explanation:**

`{ title: taskTitle }` renames a property.

A TypeScript type annotation follows the complete destructuring pattern.

---

### T2: Tuple Types and as const

**Example:**

```typescript
function getResult(): [number, string] {
  return [95, "passed"];
}

const [score, result] = getResult();

const coordinates = [41.01, 28.97] as const;

const [latitude, longitude] = coordinates;
```

**Real output:**

```text
T2 tuple: 95 passed
T2 as const: 41.01 28.97
```

**Explanation:**

A tuple describes the number and types of values at specific positions.

`as const` produces readonly tuple inference with literal types.

---

### T3: noUncheckedIndexedAccess

**Example:**

```typescript
const grades: number[] = [85, 90];

const [firstGrade] = grades;

if (firstGrade !== undefined) {
  console.log("T3 first grade:", firstGrade);
}

const emptyGrades: number[] = [];

const [missingGrade = 0] = emptyGrades;

console.log("T3 default:", missingGrade);
```

**Real output:**

```text
T3 first grade: 85
T3 default: 0
```

**Explanation:**

With `noUncheckedIndexedAccess`, TypeScript considers that an array element might be missing.

Values can have types such as `number | undefined`. Guards and defaults help handle this possibility.

---

### T4: Optional Fields and Defaults

**Example:**

```typescript
type CourseOptions = {
  credits?: number;
};

const courseOptions: CourseOptions = {};

const { credits: optionalCredits } = courseOptions;

const { credits = 3 } = courseOptions;
```

**Real output:**

```text
T4 optional: undefined
T4 default: 3
```

**Explanation:**

Optional properties may not exist. Defaults provide values when they are missing or `undefined`.

---

### T5: Compile-Time Error and Correction

**Example from `ts/types.ts`:**

```typescript
const student = {
  name: "Damla",
  age: 22
};

// @ts-expect-error Property 'department' does not exist
const { department } = student;

console.log("T5 invalid:", department);

const { name: studentName } = student;

console.log("T5 fixed:", studentName);
```

**Actual runtime output:**

```text
T5 invalid: undefined
T5 fixed: Damla
```

**Separate compiler experiment:**

A temporary file named `ts/t5-error-demo.ts` was created without `@ts-expect-error`.

```typescript
const student = { name: "Damla", age: 22 };

const { department } = student;

console.log(department);
```

The following command was executed:

```powershell
npx tsc --noEmit --strict --skipLibCheck --target es2022 ts/t5-error-demo.ts
```

**Actual compiler error:**

```text
ts/t5-error-demo.ts:2:9 - error TS2339: Property 'department' does not exist on type '{ name:string; age: number; }'.

Found 1 error in ts/t5-error-demo.ts:2
```

**Explanation:**

TypeScript detected that the `department` property did not exist on the object.

At runtime, accessing that missing property produced `undefined`.

**Correction:**

Access an existing property or define the missing property in the object and its type.

The temporary file was removed after the experiment, and `npm run check` passed.

`@ts-expect-error` is used only for this intentional T5 example.

## 5. React Props and Children: P1–P7

JavaScript examples are implemented in `js/props.jsx`, and TypeScript examples are implemented in `ts/props.tsx`.

The project uses `renderToStaticMarkup` from React DOM to generate observable HTML without a browser.

### P1: Props Object Versus Destructuring

**Example:**

```jsx
function CardA(props) {
  return (
    <section>
      <h2>{props.title}</h2>
      {props.children}
    </section>
  );
}

function CardB({ title, children }) {
  return (
    <section>
      <h2>{title}</h2>
      {children}
    </section>
  );
}
```

**Real output:**

```text
P1 A: <section><h2>Study Plan</h2>React</section>
P1 B: <section><h2>Study Plan</h2>React</section>
```

**Explanation:**

React passes one props object to each component.

Destructuring changes how properties are accessed, but both implementations produce the same HTML.

In TypeScript, `CardProps` defines `title: string` and `children?: ReactNode`.

---

### P2: Children as a Prop

**Example:**

```jsx
<CardB title="Notes">Hello</CardB>

<CardB title="Notes" children="Hello" />
```

**Real output:**

```text
P2 nested: <section><h2>Notes</h2>Hello</section>
P2 attribute: <section><h2>Notes</h2>Hello</section>
```

**Explanation:**

Content placed between component tags becomes the `children` prop.

The same value can also be passed explicitly.

### P3: Different Types of Children

**Real output:**

```text
P3 string: <div>Hello</div>
P3 number: <div>42</div>
P3 element: <div><strong>Important</strong></div>
P3 multiple: <div><span>A</span><span>B</span></div>

P3 null: <div></div>
```

**Explanation:**

Strings and numbers are rendered as text.

React elements produce HTML.

Arrays may contain multiple elements.

`undefined`, `null`, and `false` produce no visible content.

**Function example:**

```jsx
const renderMessage = () => "Hello from function";

<ChildBox>{renderMessage()}</ChildBox>
```

**Real JavaScript output:**

**Explanation:**

A plain function is not a directly renderable React child.

Calling the function first produces a renderable value. TypeScript's `ReactNode` type does not accept a plain function.

### P4: Rest Props and Spread Order

**Example:**

```jsx
function Panel({ title, children, ...rest }) {
  return (
    <section {...rest}>
      <h3>{title}</h3>
      {children}
    </section>
  );
}
```

**Real output:**

```text
P4 rest: <section id="task-panel" class="panel"><h3>Tasks</h3>Current tasks</section>
```

**Explanation:**

`title` and `children` are extracted. The other props are collected in `rest` and forwarded to the HTML element.

**Spread order example:**

```jsx
function ButtonExample(props) {
  return <button {...props} type="button">Save</button>;
}
```

**Real output:**

```text
P4 override: <button type="button">Save</button>
```

The supplied `type="submit"` was overridden by the later `type="button"` attribute.

Spread order determines which value is used.

### P5: Named Slots Versus Children

**Named props example:**

```jsx
function LayoutWithProps({ header, footer, children }) {
  return (
    <article>
      <header>{header}</header>
      <main>{children}</main>
      <footer>{footer}</footer>
    </article>
  );
}
```

**Children example:**

```jsx
function LayoutWithChildren({ children }) {
  return <article>{children}</article>;
}
```

**Real output:**

```text
P5 props: <article><header>My Tasks</header><main>Task list</main><footer>3 tasks</footer></article>
P5 children: <article><header>My Tasks</header><main>Task list</main><footer>3 tasks</footer></article>
```

**Explanation:**

Named props are useful when a component controls specific regions.

General children allow greater flexibility over the structure.

Both approaches produced the same HTML in this example.

---

### P6: Undefined Versus Null

**Example:**

```jsx
function StatusBadge({ label = "Pending" }) {
  return <span>{label}</span>;
}
```

**Real output:**

```text
P6 undefined: <span>Pending</span>
P6 null: <span></span>
```

**Explanation:**

`undefined` triggers the default value.

`null` does not trigger the default. React renders no visible text for `null`.

The TypeScript version uses `label?: string | null`.

### P7: TypeScript Types for React Props

#### ReactNode

```tsx
import type { ReactNode } from "react";

type CardProps = {
  title: string;
  children?: ReactNode;
};
```

`ReactNode` represents values that React can render.

A plain function cannot be assigned as a normal ReactNode child.

#### PropsWithChildren

```tsx
import type { PropsWithChildren } from "react";

function LayoutWithChildren({
  children
}: PropsWithChildren) {
  return <article>{children}</article>;
}
```

`PropsWithChildren` adds an optional `children` property to a props type.

#### ComponentProps

```tsx
import type { ComponentProps } from "react";

type ActionButtonProps = ComponentProps<"button"> & {
  label: string;
};
```

`ComponentProps<"button">` provides the standard HTML button prop types.

#### Accepted Examples

```tsx
<ActionButton label="Save task" disabled />

<LayoutWithChildren>
  <strong>Task details</strong>
</LayoutWithChildren>
```

**Real output:**

```text
P7 ComponentProps: <button disabled="">Save task</button>
P7 PropsWithChildren: <article><strong>Task details</strong></article>
```

#### Rejected Examples

These examples illustrate TypeScript restrictions:

```tsx
// Missing required label
<ActionButton disabled />

// Wrong label type
<ActionButton label={123} />

// A function is not a valid ReactNode
<ChildBox>{() => "Hello"}</ChildBox>
```

These examples describe type-level restrictions and were not separately compiled during the recorded experiment.

**Conclusion:**

TypeScript checks component props before execution and can prevent invalid values from being passed.

## 6. JavaScript vs TypeScript Comparison

| Topic | JavaScript | TypeScript |
|---|---|---|
| Array extraction | Extracts values at runtime | Supports inferred types |
| Tuple results | Uses ordinary arrays | Tuple types describe positions and element types |
| Missing elements | May produce `undefined` | Can detect possible `undefined` values |
| Object extraction | Accesses properties dynamically | Checks properties against object types |
| Property renaming | Uses `property: alias` | Same syntax; type annotations are separate |
| Optional defaults | Applied at runtime | Optional fields are represented in types |
| Nested destructuring | Depends on runtime data | Nested types describe expected data |
| Computed properties | Dynamic keys can be attempted | `keyof` restricts allowed keys |
| Function parameters | Supports destructured options | Option types describe accepted properties |
| Map iteration | Iterates key-value pairs | Generic types describe keys and values |
| React children | Invalid values may cause runtime issues | `ReactNode` checks renderable child types |
| HTML props | Props are passed dynamically | `ComponentProps` checks HTML prop types |

**Observation:**

JavaScript and TypeScript generally produce the same runtime results for the matching examples.

The main difference is that TypeScript adds static checking and can identify mistakes before execution.
